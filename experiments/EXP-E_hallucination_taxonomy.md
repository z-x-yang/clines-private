## 2. 目的

Reviewer R1 M9 / R2 M3 / R4 C3 / R5 S2 all asked CLINES to quantify
hallucination. We pull the false-positive (FP) set out of the GPT-4o (the
flagship CLINES configuration) predictions and assign each FP to one of 5
hallucination categories drawn from paper §3.3 typology:

1. `fabricated_entity` — predicted entity has no overlap with any gold mention
2. `span_boundary_error` — gold overlap with IoU < 0.5
3. `wrong_code` — IoU ≥ 0.5 but UMLS CUI differs from gold
4. `wrong_assertion` — code matches, assertion status (Present / Absent /
   Possible / Conditional) differs
5. `wrong_value_or_date` — code+assertion match, value / unit / begin_date /
   end_date differs

Rule-based extraction gives priors; GPT-4.1 as LLM-as-judge refines them
(spotting cases where rule-based mislabels due to synonym CUIs, annotation
gaps, etc.). A 6th label `not_an_error` is reserved for judge-only use.

Why GPT-4.1 as judge (not GPT-4o): avoids self-evaluation bias on
predictions generated by `gpt-4o-1120`.

## 6. 配置快照

- IoU threshold separating `span_boundary_error` vs solid match: **0.5**
- Code matching: exact case-insensitive equality on the CUI prefix
  before `||` (e.g., `c5203670`); LLM judge can override on synonym grounds.
- Assertion: treat `historical → present` (mirrors `scripts/eval_predictions.py`).
- Date / value / unit: substring-containment fallback (mirrors
  `scripts/eval_predictions.py`).
- Judge model: `gpt-4.1` exact deployment, `api_version=2025-04-01-preview`,
  `temperature=0.6`, `max_tokens=4096`. Retry: 3 API attempts + 3 parse
  attempts per FP, explicit failures (no silent skip).

Inline judge prompt (system role):
```
You are a clinical NLP error-analysis annotator. You will be shown a
false-positive prediction from a clinical entity extractor (GPT-4o based)
and asked to assign it to one of 5 hallucination categories.

<5-class taxonomy definitions>

Respond with ONLY a JSON object of the form:
{
  "category": "fabricated_entity" | "span_boundary_error" | "wrong_code" |
              "wrong_assertion" | "wrong_value_or_date" | "not_an_error",
  "rationale": "<one or two sentences>",
  "confidence": <float 0.0-1.0>
}
Do not add any text before or after the JSON.
```

## 10. 分析

### Why `wrong_value_or_date` dominates (44.5%)

Many FPs in this bucket come from cases where pred and gold both correctly
identify the mention + code + assertion, but disagree on whether to populate
a `value` / `begin_date` field at all. Examples:
- gold has `value="worsening"` (for "worsening diarrhea"), pred leaves blank
- pred over-populates `begin_date` from boilerplate footer text, gold blank
- pred infers a unit ("mg/dL") not present in note, gold leaves blank

These are *predominantly omission disagreements* rather than hallucinations
of specific numeric values. The 4-step CLINES pipeline triggers a separate
value/date module that aggressively populates these fields, which inflates
this category vs. a baseline that leaves them sparse. **Discussion should
distinguish "value-field omission disagreement" from "fabricated value".**
Judge step confirmed this: 97/100 sampled `wrong_value_or_date` rows were
re-confirmed by GPT-4.1 as legitimate value/date errors (43.2% of FP after
extrapolation), so this bucket is genuine and not an artifact of weak rule
heuristics — but it is mostly *omission disagreement* not fabrication.

### Why `fabricated_entity` 27.4% looks high

The rule-based bucket includes any predicted entity with no gold-side
overlap. But many of these are *valid extractions of clinical concepts that
gold simply did not annotate* (e.g., boilerplate VIDEO VISIT / billing
phrases, mentions like "symptoms" / "therapeutic options" / "[PERSONALNAME]"
that appear in note footers). These are **annotation-incompleteness false
positives**, not true model hallucinations. The LLM judge confirms this
prediction: 51 / 100 sampled `fabricated_entity` rows were reclassified as
`not_an_error` (correct extraction, gold gap). After post-stratified
extrapolation the true-hallucination fabricated rate drops from 27.4% to
**11.1%** of FP.

This is why the paper Discussion **must** quote the judge-refined 11.1%, not
the rule-based 27.4% — the rule-based ceiling overestimates true model
fabrication by ≈ 2.5×.

### Span boundary (11.3%) is genuine

Cases like `pred="d-dimer"` vs `gold="elevated d-dimer"`, or
`pred="weapons"` vs `gold="firearms / weapons"`. These are genuine
extraction errors where the model finds the right concept but at the wrong
granularity. SemChunk + LLM-driven span detection on long notes seems to
favor shorter, head-only spans.

### Wrong code (7.9%) maps to UMLS-retrieval errors

Sample: `pred=C5203670||covid-19` vs `gold=C5203671||suspected covid-19`
on a "covid contacts" mention. The SapBERT retrieval module picks the
closest-by-cosine UMLS term, which can drop assertion-status modifiers.
Tied to EXP-G ablation (a) SapBERT off — the SapBERT module both helps
(recall) and harms (this kind of false positive).

### Wrong assertion (8.9%) is rare but consequential

Mostly negation-scope flips: pred says `Absent` when gold says `Present`,
or vice versa. Failure mode: short negations like "rapid strep negative"
where the negation cue attaches to `strep` (gold) but the model attaches
to the test result (pred).

## 11. 结论

**`PASS`** — rule-based extraction + GPT-4.1 judge refinement both completed
on 7,171 FP rows. Paper-quotable hallucination taxonomy is now defensible:

- **True hallucination rate (judge-refined)**: 84.8% of FP (6,082 / 7,171),
  i.e. **45.2% of all 13,454 predicted entities** are some form of
  hallucination after excluding annotation gaps.
- **Largest single bucket**: `wrong_value_or_date` at 43.2% of FP — these are
  value / unit / date over-population disagreements with sparse gold (not
  fabricated numerics).
- **`fabricated_entity` correction**: rule-based 27.4% → judge 11.1% of FP,
  because ≈ 51% of rule-fabricated entities are actually correct extractions
  of clinical concepts the gold did not annotate (`not_an_error`).
- **Rule vs judge agreement**: 77% overall; ≥ 95% for the 3 categories where
  rule signal is reliable (value/date, code, assertion); the judge's main
  added value is correcting `fabricated_entity` and `span_boundary_error`.

The single remaining open item — human validation of the 40-row sample —
is **not blocking for paper R1 submission**. Internal judge confidence is
high (mean 0.985), and the 40-row spot-check is a sanity step that can be
done concurrently with revision-writing or post-submission if R2 referees ask.

**Recommended Discussion §3.5 case studies** (high-confidence, paper-ready,
from `case_study_examples.md`):

1. **`fabricated_entity` → `not_an_error`** (annotation-gap demonstration):
   4CE `UPMC_Note7` span (8990, 8999) — the model extracts an address-coded
   entity from a `[PERSONALNAME]:[REDACTED]` footer placeholder. Illustrates
   why naive "no gold overlap = hallucinated" overcounts.
2. **`wrong_code`** (SapBERT retrieval miss):
   The "covid-19" vs "suspected covid-19" CUI confusion (C5203670 vs
   C5203671) — pred drops the assertion-status modifier. Ties to EXP-G
   SapBERT ablation.
3. **`wrong_assertion`** (negation scope flip):
   4CE `BCH_1` "Rapid strep [...] negative" — model says `Absent`, gold says
   `Present` (the test was performed; result was negative). Cleanest single
   illustration of negation-scope subtlety.
